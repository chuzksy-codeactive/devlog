# DevLog LinkedIn Post Drafts

## Post 1 — Builder/General Audience

Every sprint comes with its own challenges, resolutions, feedback, and lessons.

I built a habit of reflecting after each sprint: what worked, what did not, and what I need to improve. I also documented these points so I had better conversations in my biweekly 1:1 with my Line Manager.

While doing that, I kept thinking:

- What if this became a real work journal?
- What if parts of it could become a public, professional portfolio?
- What if recruiters could explore real sprint evidence instead of static CV bullets?
- What if AI could answer specific questions about your practical experience?

That idea became **DevLog**.

Instead of a static CV or generic portfolio, **DevLog turns sprint work into structured, privacy-safe, recruiter-ready proof of impact**.

### What DevLog includes
- **Creator side:** CV upload, GitHub import, sprint journals, and learning logs
- **Viewer side:** recruiter-friendly timeline of real engineering work
- **AI layer:** privacy-first sanitization before publishing, plus candidate-specific Q&A

It is built for developers first, but the same workflow also helps **Business Analysts, DevOps engineers, and Product Managers** capture outcomes, decisions, and lessons in a shareable format.

### Stack behind it
- **Frontend:** Next.js 16 + React 19 + TypeScript  
- **Backend:** ASP.NET Core Web API (.NET 10)  
- **Data:** PostgreSQL + EF Core 10 + pgvector  
- **Cloud:** Azure App Service + Azure Static Web Apps  
- **Ops:** Application Insights telemetry  
- **Email:** Postmark
- **Embeddings:** OpenAI embeddings  
- **AuthN/AuthZ:** Clerk  
- **CI/CD:** GitHub Actions

I’m running a **controlled beta** to keep quality high and infrastructure/AI costs sustainable while we validate usage patterns.

## Post 2 — Recruiter-Targeted

Recruiters: I’m building **DevLog** to make technical screening faster and more evidence-based.

Instead of relying only on keyword resumes, DevLog gives you a structured timeline of a candidate’s sprint work and an AI assistant you can ask:

- “What Azure production experience do they have?”  
- “Have they worked with SQL performance optimization?”  
- “What outcomes did they deliver and at what scale?”

### Why this is useful
- You get **candidate-specific technical evidence**, not generic AI summaries  
- You can evaluate depth in cloud/data/backend work more quickly  
- Public entries are processed through a privacy-focused sanitization flow
- It is useful beyond software engineers, including **Business Analysts, DevOps engineers, and Product Managers** who also need measurable work evidence
